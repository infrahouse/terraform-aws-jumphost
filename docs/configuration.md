# Configuration

All input variables of the InfraHouse jumphost module, grouped by purpose.
The authoritative list with types and defaults lives in the
[README](https://github.com/infrahouse/terraform-aws-jumphost#requirements),
generated by terraform-docs.

## Required Variables

| Variable | Description |
|----------|-------------|
| `environment` | Environment name (e.g. `production`). Passed to instances as a Puppet fact and used in the CloudWatch log group name. |
| `subnet_ids` | Subnets where the jump host instances run. EFS mount targets are created in each. |
| `nlb_subnet_ids` | Subnets for the Network Load Balancer. Public subnets make the NLB internet-facing, private subnets make it internal. |
| `route53_zone_id` | Route53 zone where the jump host DNS record is created. |
| `alarm_emails` | At least one email address for CloudWatch alarm notifications. Each address must confirm the SNS subscription email before notifications are delivered. |

Minimal configuration:

```hcl
module "jumphost" {
  source  = "registry.infrahouse.com/infrahouse/jumphost/aws"
  version = "5.0.0"

  environment     = "production"
  subnet_ids      = module.vpc.subnet_public_ids
  nlb_subnet_ids  = module.vpc.subnet_public_ids
  route53_zone_id = data.aws_route53_zone.example.zone_id
  alarm_emails    = ["ops-team@example.com"]
}
```

## Instances

| Variable | Default | Description |
|----------|---------|-------------|
| `instance_type` | `t3a.micro` | EC2 instance type. |
| `ami_id` | latest Ubuntu Pro | Override the AMI. By default the latest Ubuntu Pro image for `ubuntu_codename`. |
| `ubuntu_codename` | `noble` | Ubuntu release. Only `noble` is supported at the moment. |
| `root_volume_size` | `30` | Root EBS volume size in GB. |
| `keypair_name` | generated | EC2 key pair added to the instance. A throwaway key pair is generated if not set. |

## Auto Scaling and Spot Instances

| Variable | Default | Description |
|----------|---------|-------------|
| `asg_min_size` | number of subnets | Minimum number of instances. |
| `asg_max_size` | number of subnets + 1 | Maximum number of instances. |
| `on_demand_base_capacity` | `null` | If set, the ASG requests spot instances; this many instances stay on-demand. |

Setting `on_demand_base_capacity = 0` runs the whole fleet on spot instances:

```hcl
module "jumphost" {
  # ...
  on_demand_base_capacity = 0
}
```

## EFS Home Directory

| Variable | Default | Description |
|----------|---------|-------------|
| `efs_creation_token` | generated per deployment | Unique reference for the EFS file system. Set explicitly only to keep a file system created by module version < 6.0 (old default: `jumphost-home-encrypted`). |
| `efs_kms_key_arn` | AWS managed key | KMS key for EFS encryption. |

!!! warning

    Changing the creation token on an existing deployment destroys and recreates the
    EFS file system — all home directories are lost.

## DNS

| Variable | Default | Description |
|----------|---------|-------------|
| `route53_hostname` | `jumphost` | Record name created in the Route53 zone. |
| `route53_ttl` | `300` | TTL of the record, in seconds. |

## CloudWatch Logging and Monitoring

| Variable | Default | Description |
|----------|---------|-------------|
| `log_retention_days` | `365` | Log retention. Must be a valid CloudWatch retention period (0 = never expire). |
| `cloudwatch_kms_key_arn` | AWS managed key | KMS key for log group encryption. |
| `cloudwatch_namespace` | `Jumphost/System` | Namespace for custom metrics published by the instances. |

The module creates an SNS topic for alarm notifications and subscribes every address
in `alarm_emails` (see [Required Variables](#required-variables)). A CPU utilization
alarm (>90%) always publishes to this topic; its ARN is exposed as the
`alarm_sns_topic_arn` output for additional subscriptions (PagerDuty, Slack, etc.).

The log group `/aws/ec2/jumphost/<environment>/<route53_hostname>.<zone>` is always created —
logging is a mandatory security feature and cannot be disabled.

## IAM

| Variable | Default | Description |
|----------|---------|-------------|
| `extra_policies` | `{}` | Map of policy name → policy ARN to attach to the jump host role. |
| `instance_role_name` | generated | Name for the instance role, if you need a predictable one. |

Two ways to grant additional permissions:

```hcl
# Method 1: at module call time
module "jumphost" {
  # ...
  extra_policies = {
    "ssm-access" = "arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore"
  }
}

# Method 2: attach to the role after the fact
resource "aws_iam_role_policy_attachment" "additional" {
  role       = module.jumphost.jumphost_role_name
  policy_arn = aws_iam_policy.your_policy.arn
}
```

## SSH Host Keys

| Variable | Default | Description |
|----------|---------|-------------|
| `ssh_host_keys` | generated | List of host key objects (`type`, `private`, `public`). By default the module generates RSA, ECDSA, and ED25519 keys and keeps them in Terraform state. |

Provide your own keys to preserve an existing jump host identity:

```hcl
module "jumphost" {
  # ...
  ssh_host_keys = [
    {
      type    = "ed25519"
      private = file("secrets/ssh_host_ed25519_key")
      public  = file("secrets/ssh_host_ed25519_key.pub")
    }
  ]
}
```

## Cloud-Init and Puppet

| Variable | Default | Description |
|----------|---------|-------------|
| `packages` | `[]` | Extra APT packages to install at boot (`nfs-common` is always added). |
| `extra_files` | `[]` | Files to create on the instance (`content`, `path`, `permissions`). |
| `extra_repos` | `{}` | Additional APT repositories (`source`, `key`). |
| `puppet_custom_facts` | `{}` | Custom Puppet facts, deep-merged with module-provided `jumphost.*` facts. |
| `puppet_debug_logging` | `false` | Enable Puppet debug logging. |
| `puppet_manifest` | `site.pp` for the environment | Path to the Puppet manifest to apply. |
| `puppet_root_directory` | `/opt/puppet-code` | Where the Puppet code lives. |
| `puppet_environmentpath` | `{root_directory}/environments` | Puppet directory environments path. |
| `puppet_hiera_config_path` | `{root_directory}/environments/{environment}/hiera.yaml` | Hiera configuration path. |
| `puppet_module_path` | environment + common modules | Puppet module lookup path. |

The module always provides the facts `jumphost.cloudwatch_log_group` and
`jumphost.cloudwatch_namespace`; user-provided facts take precedence on conflicts,
and both sets are preserved on a deep merge.

## Outputs

| Output | Description |
|--------|-------------|
| `jumphost_hostname` | Fully qualified DNS name for SSH access. |
| `alarm_sns_topic_arn` | SNS topic receiving CloudWatch alarm notifications. |
| `jumphost_asg_name` | Auto Scaling Group name. |
| `jumphost_role_name` / `jumphost_role_arn` | Instance IAM role, for attaching extra policies. |
| `jumphost_instance_profile_name` / `jumphost_instance_profile__arn` | Instance profile details. |
| `cloudwatch_log_group_name` / `cloudwatch_log_group_arn` | CloudWatch log group for audit trails. |
